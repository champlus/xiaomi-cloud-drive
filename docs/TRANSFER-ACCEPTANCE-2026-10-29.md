# 传输与 Finder 验收 · v0.1.3

传输页改为「正在传输 / 已完成」两个原生分段按钮控制的列表。正在传输显示每个文件的路径、进度、实时速度和阶段；已完成显示方向、大小和时间。失败或中断单独列在未完成区域，保留原有上传恢复副本入口。

速度取最近三秒内实际传输的字节，三秒没有新数据时归零。发送完数据后还会等待云端提交与替换完成，不会在百分比到达 100% 时提前记录成功。短时间内同一个文件的预览、范围下载会合并，完整下载记录优先于部分下载；预览主动关闭不会作为传输失败。Finder 的空文件占位创建不计为照片已完成。

记录保存在本机私有目录，文件权限为 0600；按小米账号隔离，保留最近 200 条结束记录。服务重启时，原有进行中的记录会标为中断，不会变成完成。查询进度只读本地状态，不触发额外云端查询。退出和开发更新也检查正在下载的文件，避免中途重启服务。

## 小照片卡住的调查

用户截图为约 374 KB 的照片，Finder 停在 0 字节，同时旧传输页反复显示同名上传日志。本机只读检查发现：接收临时文件已经有 374,144 字节，任务仍处于 receiving，停留超过两分钟。后续出现锁冲突和重试，不能把这一段时间归因于云端带宽。

[Apple WebDAVFS 源码](https://github.com/apple-oss-distributions/webdavfs/blob/a239d37d7407700119e9c92f66f38ab0a296cb0f/mount.tproj/webdav_network.c)的流式 PUT 使用 X-Expected-Entity-Length 声明文件大小。完全本地的 TCP 回归复现了文件字节已经发完、但结束块未发送时，原实现一直等待 EOF 的情况。

修复后按声明长度接收，并短暂检查是否存在超出声明的字节；接收完整但流未关闭时，正常返回响应并关闭该请求的连接。声明长度过小、收到多余数据或提前结束时拒绝发布，保留本地恢复副本及云端原文件。普通 Content-Length 上传和无大小声明的上传保持原有完整性检查。

## 验证结果

已通过 Go 单测、竞态检测、静态检查和原生模型测试，覆盖速度归零、提交失败、历史恢复、账号隔离、保留上限、范围下载、预览合并、客户端取消、只读元数据不产生传输、更新保护和 Finder 流式请求。SwiftUI 的速度、进度条和两个页面切换用标明「本地界面核对」的模拟数据窗口检查，没有为观察进度额外制造大文件云端传输。

真实账号仅在独立测试目录复制一个 374,144 字节的生成图片，使用现有 Finder 挂载卷的文件操作。上传请求完成耗时为 1.992 秒；随后单次 CLI 下载与本地原文件 SHA-256 一致，上传和下载均出现在完成列表。Finder 挂载路径的读取可能直接命中本机缓存，因此另用 CLI 的实际下载请求验证下载记录，未把缓存读取伪装成网络下载。测试没有重登、没有故障注入或压力测试。

这是一次小文件样本，不代表所有网络、大目录或大文件的固定耗时。测试目录只含生成的图案，验收后移入云端最近删除，用户照片与个人材料未修改。
